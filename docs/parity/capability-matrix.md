`current_tauri` 只使用五种状态：`baseline` 表示当前已有并需要冻结，`implemented` 表示当前阶段界定的代码目标已实现并具备自动验证（不代表已经完成 Windows 实机或 release 验证），`partial` 表示已有部分实现，`missing` 表示尚未迁移，`blocked` 表示等待 `blocked_by` 指明的外部项目、证据或维护者决定；`blocked` 行必须提供非 `none` blocker。

`parity_level` 只使用 `P0`、`P1`、`P2` 表达能力重要性。`convergence_mode` 只使用 `parity`、`architecture-replacement`、`intentional-exclusion`，分别表示行为对齐、架构替代和明确排除。验证栏中的 `Field Validation Pending (non-blocking)` 只阻止 `Field Validated / Release Verified`，不降低已经完成的代码状态。

## M2 Playback 2.0（Code Complete / Automated Verification Complete）

`PlaybackAudioRuntime` 现独占两个 lifetime deck、Audio Graph、fade、prepared owner、恢复探针与输出路由。Application session 只接受同时匹配 exact issued load 与 loaded source URL 的 `ownerchange`；pending 或旧 deck 的原生媒体事件不能提交 store。queue/mode/gapless authority 变化会立即撤销 prepared handle，清空当前曲目会进入 `stop()` 并释放 physical owner 与探针资源。

Album handoff 使用统一的 preload/preroll/crossfade authority：物理 owner commit 后立即 compare-and-commit store，采用成功再发布 `adopted` ownerchange；store rejection、stale intent、play failure 与新 intent 均可回滚到 outgoing。Visual 只取得只读 `AudioFrameSource`，不取得 Controller、HTMLAudioElement、AudioContext 或 sink mutation。

自动证据覆盖 play/ready/stall/Graph/audibility budgets、diagnostics 深冻结/脱敏、typed preference、逐设备状态、默认 sink 恢复、240 次切歌平台和 Sidecar freeze。正式 WebView2 连播与 720ms 听感、不同 codec/sample-rate、真实 `setSinkId`/设备拔插/四路 mirror/Virtual Bridge、前后台/睡眠、真实静音误判、30–60 分钟 Windows soak、进程树/CPU/glitch/长期内存仍为 `Field Validation Pending (non-blocking)`；只阻止 `Field Validated / Release Verified`。
