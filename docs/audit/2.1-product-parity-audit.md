## 结论先行

`RC_READY = NO`。

本次对上游用户可见面建立了 101 个稳定 surface ID。没有任何 surface 获得 `EXACT`：当前自动化能证明若干组件存在、协议结构可解析、确定性预算可通过，但不能证明与上游的几何、信息架构、交互顺序、真实 provider 数据或 Windows/WebView2 行为一致。

| 状态 | 数量 | 解释 |
|---|---:|---|
| `EXACT` | 0 | 没有足够的上游 golden + 当前截图/交互/现场证据 |
| `CLOSE` | 9 | 主路径大体对应，但仍缺现场或语义验证 |
| `PARTIAL` | 45 | 有实现或局部能力，缺上游关键面、行为或数据闭环 |
| `MISSING` | 11 | 未发现等价产品面或当前明确未提供 |
| `REGRESSION` | 15 | 当前可见行为、错误状态或架构结果比上游退化 |
| `DEBUG_LEAKAGE` | 3 | 上游没有、却能由生产构建/正常路径到达的调试或内部诊断面 |
| `UNVERIFIED` | 18 | 代码或静态证据不足以证明，不把“存在”当作“通过” |

最小 RC blocker 集合：

1. 修复审计/发布验证权威：把视觉、完整 surface、真实字段、Windows/WebView2 和性能现场证据纳入 gate；现有 contract、M4、M8、reviewed-delta 不能单独签发 parity。
2. 从生产可达路径移除 visual audio debugger、M4 fixture route 和默认 raw desktop diagnostics，或彻底隔离到开发/测试构建并增加反向 gate。
3. 修复 Home 的推荐与天气电台 schema failure；当前正常路由截图持续显示 `推荐预览载入失败` 和 `天气电台载入失败`。
4. 完成 cover pipeline 的 Windows/WebView2 field gate：QQ 空 `albummid`、shared semantic contract、provider-aware Referer/CSP 与 DOM/WebGL canonical proxy 已自动化修复；仍需真实 provider DOM/WebGL 样本签收。
5. 恢复上游 player shell 和 Visual Console 的核心信息架构与交互：mini queue、metadata/detail、Cuefield、歌词 offset、auto-hide/immersive、连续 console sections、archive 等不能用 Settings Workbench 的节点存在替代。
6. 对 Stage Lyrics 做真实 Windows/WebView2 50 次转场测量，满足 p95/p99/max、long-task、texture upload 和 GPU gate 后才能签性能 parity。

## 专项审计

### Visual Console

结论：`REGRESSION / P1`。上游是连续、可折叠、自动隐藏的“视觉控制台”；当前 `VisualControlPanelHost` 组合 `SettingsWorkbench`，是六 tab 设置应用。当前截图标题为“视觉控制台 · 设置工作台”，默认首屏只有预设和少量 slider；用户视觉存档、camera gesture、hotkeys 等缺失或不等价。参数名存在不能证明同位、顺序、密度、默认状态、重置/持久化与上游一致。详见 [visual-console-parity.md](visual-console-parity.md)。

### Bottom Bar / Player Shell

结论：`REGRESSION / P1`。上游 DOM 明确包含 mini queue 显式关闭、可点击 metadata/detail、Cuefield AutoMix、歌词时差 `-0.1/0/+0.1`、volume/fade、auto-hide/immersive/free-camera hints。当前 `PlayerConsoleHost` 有 transport/queue/volume/lyrics/fullscreen 等局部节点，但队列操作、metadata、popover 层级、3D shelf 控件和 auto-hide 语义不等价。详见 [player-shell-parity.md](player-shell-parity.md)。

### Debug Leakage

结论：`S099-S101` 都是 `DEBUG_LEAKAGE / P1`。`visual-audio-debug.ts` 被生产 visual composition 导入，支持 URL、localStorage、Ctrl+Alt+D 和全局 debug API；`?m4-parity=1` 在 `main.tsx` 旁路正常 bootstrap；`refreshDiagnostics()` 在正常 startup 无条件运行并把内部诊断暴露到可见 UI。生产 dist 已出现独立 `M4ParityRoot` chunk。详见 [debug-leakage.md](debug-leakage.md)。

### Cover Pipeline

结论：`PARTIAL / P1 FIELD BLOCKER`。QQ mapper 已对空/缺失 album mid 返回空 cover；shared schema 拒绝 malformed 与 `M000.jpg`；native proxy 使用安全 hostname policy；DOM/CSS 与 WebGL 统一经 MediaUrlPort；production CSP 明确允许 canonical custom/local path，cover 不再依赖 provider direct CDN。自动化通过不等于 Windows/WebView2 field verified，Kugou 真实 fixture 与五类 DOM/WebGL field matrix 仍 pending。详见 [cover-pipeline.md](cover-pipeline.md)。

### Stage Lyrics 性能

结论：`REGRESSION / P1`，但真实数字仍 `UNVERIFIED`。`stage-build-coordinator` 只记录 phase timing，不在 8ms 超预算时 yield/fail；cache miss、seek、translation/karaoke 场景仍可能在关键帧同步完成 `buildLyricForText`、CanvasTexture 和 geometry/material。M8 deterministic gate 通过，只证明合成 fixture，不证明 Windows/WebView2。建议 gate：frame p95 ≤16.7ms 且不高于上游 +2ms、p99 ≤25ms、max ≤50ms、>33ms ≤1、longtask=0、stage peak ≤4.2ms、upload CPU ≤3ms、prewarm ≥95%、GPU p95 增量 ≤10%。详见 [stage-lyrics-performance.md](stage-lyrics-performance.md)。

## 自动化结果与误报

本轮只读验证结果：

- `bun test scripts/architecture/contract-parity.test.ts`：4/4 通过；只覆盖 `SongUrlResult`、`Track`、`PlaylistDetail`、`RecommendationPage` 的结构 golden。
- Visual/Player/legacy composition 组件测试：57/57 通过；主要是节点/字符串/行为存在性，不是上游截图、几何和交互顺序。
- `bun test packages/visual-engine/src/stage-lyrics`：通过；不能替代 WebView2 field 性能。
- `bun run typecheck`：通过。
- `bun scripts/perf/m8-budget.mjs`：deterministic gate 通过；不能替代真实曲目、provider、GPU/long-task 测量。
- `bun run web:build`：通过，但最大 JS chunk 约 1.99 MB（gzip 约 573 KB），且产物含独立 `M4ParityRoot` chunk；这是发布隔离与启动性能风险，不是 parity 通过证据。
- Rust 测试/编译出现 dead-code warnings；目前不单独判为 RC blocker，但要在 release lint 策略中有明确处置。

关键误报：

1. `settings.workbench` 的六 tab、preset 和 slider 被视为 Visual Console “implemented”；实际上 S046/S047/S049/S057/S060 等上游面仍退化或缺失。
2. D1 Stage Lyrics “complete” 只证明 engine/fixture 通过；S033/S043 没有 upstream golden、真实 transition p95/p99/GPU 证据。
3. M4 fixture root/evidence model 证明了合成场景可启动、resident/pending/upload count；不能证明完整 Home、播放器、provider、cover、lyrics transition parity。
4. capability matrix 的 `available:true/online` 是静态返回；不能证明登录、搜索、播放、封面或真实网络可用。
5. “Spotify blocked” 与 Rust adapter/ProviderId 已注册相冲突；在未明确 scope 前不能把跨层不一致写成完成。
6. `reviewed-delta-status.md` 的“仅 protected release env blocker”不成立：本审计已确认 P1 Home error、Visual Console/player regression、cover 缺陷、debug leakage 和 lyrics gate 缺口。

分层判定必须保持独立：Layer 1 contract/unit；Layer 2 component behavior；Layer 3 upstream golden visual；Layer 4 full product route；Layer 5 Windows/WebView2 field；Layer 6 performance field。只有 Layer 3+4 才能称视觉 verified；行为 parity 至少需要 4+5；性能 parity 必须包含 6。

## 无效或需降级的历史结论

以下结论不能继续作为 2.1 RC authority：

- D1 “Stage Lyrics / Visual complete”：降级为实现存在、产品 parity 未证，并且 S033/S043 为 regression 风险。
- `settings.workbench` “Visual Console implemented”：降级为 PARTIAL/REGRESSION。
- queue drag-sort、lyric offset、visual archive、camera gesture、hotkeys、wallpaper library/WGC、Cuefield 统一标为 POST_2_1：这是未经产品取舍的 backlog 建议，不是上游 parity 结论；其中 queue/offset/archive/Cuefield 直接影响上游核心 UX，应先由产品明确 RC scope。
- “Native API/provider order/local library/playlist complete”：最多表示 Layer 1/部分 Layer 2；真实 provider、重启、cover、Windows field 未完成。
- “只剩 protected release environment blocker”：与本报告已证 P1 blocker 矛盾，必须废止。

## 修复与验证顺序

### Wave 0：修复权威

建立 101-item manifest、状态模型（Code Present / Automated / Visual / Field 分离）、上游 golden 截图和交互 oracle；把现有 M10/reviewed-delta 降为历史记录。修正架构测试中把旧 hostname/节点存在当成 parity 的断言。

### Wave 1：Release hygiene 与数据故障

隔离/删除 S099-S101；补反向构建检查。抓取 Home recommendation/weather 的原始 `{ok,data,error}` envelope，修复 `WeatherRadioResponse` 与 `RecommendationPage` 语义 schema/fixture/adapter；capability 只报告真实可探测状态。

### Wave 2：Cover 与媒体协议

为 provider cover 建立空 mid、坏 URL、非 image content、fallback、stale refresh contract；QQ mapper、provider-aware Referer、canonical proxy、CSP 与 lifecycle 自动化已完成。剩余 gate 是用户确认的 Kugou fixture，以及同一 packaged Windows/WebView2 build 的 provider/local DOM + WebGL field matrix。

### Wave 3：Player shell

先恢复 bottom bar/mini queue/metadata/detail/lyric offset/volume-fade/auto-hide/immersive 的上游 IA，再实现或明确 Cuefield/drag-sort scope。测试应包含截图 geometry、键盘、popover close、queue mutation 和真实 media lifecycle。

### Wave 4：Visual Console

把 Settings Workbench 拆回连续 sections/折叠区；补 archive、camera/position、cover picker、完整 lyric/color/background/performance controls、hotkeys 和 wallpaper scope；用 upstream/current 同分辨率 golden 做视觉 diff。

### Wave 5：Stage Lyrics 性能

先将 build/raster/texture upload/disposal 变为预算可执行的分帧调度，再在 50 次真实换行、seek、translation、karaoke、cache miss 场景采集 PerformanceObserver、Chrome/WebView2 trace、React commit、allocation/GC、Main/Renderer/GPU 指标。

### Wave 6：Provider / library / desktop field

逐 provider 做 login/search/playlist/detail/cover/playback/logout 样本；明确 Spotify scope；补本地导入、拖排、album/detail、tray、DPI、多屏、WGC、updater、N-1 upgrade field。

### Wave 7：RC sign-off

按 Layer 1→6 顺序重新跑 contract、component、golden visual、full route、Windows/WebView2、performance gates；任何 `REGRESSION`、`DEBUG_LEAKAGE` 或 P1 `MISSING` 保留即 `RC_READY=NO`。只有所有 blocker 关闭并附证据链接，才可生成 release candidate。

## 最终 RC 判定

`RC_READY: NO`

在以下条件全部满足前不得改为 YES：

- S099-S101 不再生产可达，且构建产物无 M4/debug route 泄漏；
- Home recommendation/weather schema failure 已有原始 envelope、修复测试和现场截图；
- QQ empty-mid、provider-aware cover proxy/CSP、DOM/WebGL media URI 已通过 semantic/automated gates，并补齐用户确认的 Kugou fixture与 packaged WebView2 field matrix；
- Player Shell 与 Visual Console 的 P1 信息架构/核心交互完成 upstream golden 对拍；
- Stage Lyrics 真实 field 性能满足 gate；
- 101 surface manifest 的 P1 项全部有 Layer 3/4/5/6 所需证据，未验证项不再被标为 complete；
- provider scope（特别是 Spotify）由产品明确，并且 shared schema、capability matrix、bridge、UI 一致。
